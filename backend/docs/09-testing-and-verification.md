# 09. Проверка выполнения

Работа считается завершённой только после проверки заявленных acceptance criteria на том уровне, который соответствует риску изменения.

## Обязательные действия

1. Проверьте diff, ограничение scope и незатронутые чужие изменения.
2. Запустите доступные локальные быстрые проверки: lint, typecheck, unit tests, сборку (по scripts проекта).
3. Для изменения поведения проверьте фактический сценарий в приложении/сервисе. Для auth/сессий/БД/денег/PII — обязательны соответствующие интеграционные проверки и negative cases.
4. Для миграций, оптимизаций и новых проверок применяйте E2E, property или differential, где это повышает уверенность ([12](12-verification-techniques.md)).
5. Запишите команду, окружение, точный SHA/версию, результаты и путь к артефактам. Используйте [шаблон](templates/verification-report.md).

## Недоступность окружения

`SKIP`, `BLOCKED`, `FLAKY`, timeout и `SETUP_FAILURE` не подтверждают корректность. Не повторяйте flaky test до случайного зелёного результата и не добавляйте `sleep`, чтобы спрятать гонку. Фиксируйте первопричину и эскалируйте после нескольких предметных попыток.

Тест, написанный тем же агентом, полезен, но не заменяет независимую проверку инвариантов и production-like поведения.
