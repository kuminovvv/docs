# 02. Workflow задачи

Нетривиальная задача (несколько затронутых файлов, изменение поведения, shared-кода, архитектуры или риск регрессии):

1. Прочитайте релевантные правила, проверьте Git-status и разрешённые действия.
2. Зафиксируйте goal, scope, acceptance criteria, риски и план в `tasks/todo.md` (если этот каталог существует или создание согласовано).
3. Составьте минимальную карту затронутых контрактов и тестов. Не устраивайте переписывание соседних модулей.
4. Изменяйте код малыми шагами. Для каждого изменения поведения добавьте проверку, если она практически осуществима.
5. Запустите быстрые проверки, затем риск-ориентированные интеграционные/E2E, при необходимости property/differential.
6. Сверьте результат с критерием приёмки; проинспектируйте diff. Отметьте реально выполненные команды, даты, SHA и статусы в отчёте/`tasks/todo.md`.
7. Если пользователь скорректировал повторяющийся паттерн ошибки, добавьте урок в `tasks/lessons.md` с причиной, правилом и триггером (не каждую мелочь).

Формулировка «готово» запрещена, если не проверены обязательные для scope критерии. При блокере передайте выполненную работу и точную причину с непроверенными шагами.
