# Backend: БД, конкурентность и целостность данных

- Для конкурентных операций проверяйте lock scope, идемпотентность и SQL-инварианты на реальной изолированной тестовой PostgreSQL.
- Для БД сохраняйте транзакционные инварианты, подготовленные запросы, миграции, retention/legal hold/audit **по требованиям конкретного проекта**.
- `429` (rate limit) сам по себе не подтверждает дедупликацию: проверяйте фактическое число строк и side effects в БД.
- Тестовые fixtures должны соответствовать security/audit-инвариантам; не обходите требования ради прохождения теста.
- Не используйте production credentials и production DB без отдельной авторизации.

Применяйте [negative cases и проверки миграций](testing.md), если они относятся к изменению.
