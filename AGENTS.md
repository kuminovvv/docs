# Контракт ИИ-агента

Этот файл — **корневая точка входа**. Детали: [docs/README.md](docs/README.md). Читайте только документы, относящиеся к задаче.

## Непереговорные правила

1. Действуйте по фактическому запросу пользователя и ограничениям проекта; не придумывайте требования. Противоречия кода, тестов и документации **выявляйте**, а не разрешайте молча.
2. Перед изменениями изучите точку входа, контракты, зависимости, вызовы, тесты и состояние Git. Не читайте весь репозиторий без причины ([01](docs/01-context-loading.md)).
3. Для нетривиальной задачи зафиксируйте план, границы и критерии приёмки. Не объявляйте задачу завершённой без воспроизводимых проверок ([02](docs/02-task-workflow.md), [09](docs/09-testing-and-verification.md)).
4. Работайте с минимальным, объяснимым diff. Не перезаписывайте чужую незакоммиченную работу; используйте отдельный worktree/ветку при необходимости ([10](docs/10-git-and-delivery.md)).
5. **PASS только при исполненной проверке с подтверждением результата.** `SKIP`, таймаут, отсутствие окружения, флейк и `SETUP_FAILURE` — не `PASS`. Критические проверки fail-closed ([13](docs/13-review-and-gates.md)).
6. Для изменений поведения запускайте доступные целевые тесты, сборку/типизацию и, где возможно, фактический сценарий в работающем приложении. Подбирайте E2E/property/differential к риску ([12](docs/12-verification-techniques.md)).
7. Новая реализация не может ослаблять собственный verifier, обходить security/privacy-проверки или модифицировать контрольные правила ради зелёного статуса. Изменения verifier проходят отдельное ревью относительно базовой версии.
8. Не раскрывайте секреты, ПДн и конфиденциальные артефакты в коммитах, внешних ИИ, логах и отчётах. Не обращайтесь к production без явного разрешения ([14](docs/14-security-and-privacy.md)).
9. **Не выполняйте push, merge, выпуск тегов, CI-триггер, deployment или внешнюю передачу данных без явной авторизации**, если разрешение не установлено в конкретном проекте. Создание локального коммита и работа в разрешённой изолированной ветке допустимы в рамках задачи.
10. В конце сообщите: что изменено, точные выполненные проверки и результаты, что не проверено, остаточные риски и ссылки/пути артефактов. Не маскируйте неопределённость.
