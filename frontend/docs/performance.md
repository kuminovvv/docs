# 07. Производительность

Оптимизация начинается с измерения: метрика, сценарий, baseline, изменение, повторное измерение. Не добавляйте `useMemo`/`useCallback` без причины.

- Параллелизуйте независимые async-операции, если их порядок не нужен и это не нарушает ограничения по concurrency/нагрузке.
- Избегайте каскадных `useEffect` для derived state — вычисляйте значение из исходных props/state или используйте memo при реальной стоимости вычисления.
- `useCallback` оправдан для стабилизации identity, когда это даёт эффект (например, memoized child/dependency); сам факт передачи callback в props недостаточен.
- Не создавайте лишние объекты и константы в hot path, но не выносите данные только ради стиля.
- Для тяжёлых client-only виджетов используйте lazy/dynamic loading с сохранением доступности и корректного SSR behavior.
- Предпочитайте импорт конкретных модулей; проверяйте tree-shaking и bundle analyzer вместо предположений.
- Для длинных списков рассматривайте virtualization по **реальной DOM-нагрузке**, а не по жёсткому порогу 100 элементов.
- Для поиска/скролла/resize применяйте debounce/throttle только если UX и измерения оправдывают задержку.
- После оптимизации проверяйте parity поведения, keyboard navigation, SSR/hydration и данные у границ.

Минимальное доказательство: воспроизводимый сценарий, до/после, устройство/окружение, отсутствие заметной регрессии.
