# 14. Безопасность, ПДн, секреты

- Не выводите секреты, токены, cookie, полный auth header, ключи, ПДн и приватные пользовательские данные в commits, CI artifacts, issue, screenshots, traces и prompts внешних моделей.
- При сборе логов и тестовых доказательств используйте синтетические данные либо явную минимизацию/редакцию. Проверяйте утечки в headers, query string и exception traces.
- Внешняя передача данных через SDK, telemetry, push, captcha, AI API, CDN или error reporting требует выяснения реального получателя, цели, состава данных и отдельного разрешения/юридической проверки там, где применимо. Недостаточно «выключенного» флага без проверки runtime egress.
- AuthN/AuthZ — на сервере для каждого критического endpoint/action; проверяйте RBAC/ownership, IDOR, CSRF, expiration/rotation, rate limit и replay по угрозам.
- Для БД сохраняйте транзакционные инварианты, подготовленные запросы, миграции, retention/legal hold/audit по проектным требованиям.
- Тесты/профилирование — на sandbox/test DB. Доступ к production и реальным данным только при явной авторизации и точно согласованном scope.
- Если формальная оценка соответствия требованиям закона не подтверждена документами и актуальной проверкой, статус — **не подтверждено**. Правила этого репозитория не являются юридическим заключением.

Для Soobota существовавший в архиве реестр трансграничных передач и флаги отдельных провайдеров относятся к конкретной production-конфигурации и должны храниться в соответствующем приватном проекте, а не применяться универсально.
