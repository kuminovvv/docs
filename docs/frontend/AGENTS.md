# AGENTS.md — frontend

**Область:** задачи во frontend-проектах. Это проектная точка входа, а не обязательное правило для backend или всех репозиториев. До применения проверьте реальный стек, версии из package.json/lockfile и архитектуру целевого проекта. Если проект использует другой стек, не навязывайте React, Next.js или FSD.

## Контракт выполнения

1. Следуйте запросу и утверждённым требованиям проекта; при конфликте кода, тестов и документации фиксируйте расхождение, не выбирайте молча.
2. Перед изменениями изучите затронутую точку входа, зависимости, публичные контракты, соседние компоненты, тесты и состояние Git. Не загружайте весь репозиторий без необходимости.
3. Для нетривиальных изменений определите scope, план, критерии приёмки и риски. Изменяйте код минимально и по принятому стилю, не создавайте абстракции только ради шаблона.
4. Учитывайте реальные версии React, TypeScript, Next.js и библиотек, различайте App Router/Pages Router, используйте официальные release notes и инструкции миграции. Не включайте устаревшие experimental-настройки и не применяйте version-specific API без проверки.
5. Соблюдайте серверные/клиентские границы, авторизацию серверных мутаций, приватность кеша и доступность UI. Не обходите проверки, чтобы получить зелёный статус.
6. Проверяйте изменения с помощью доступных lint, typecheck, unit/build и релевантных browser/E2E сценариев. Для auth, routing, caching, hydration и персональных данных добавляйте негативные проверки.
7. Обозначайте PASS только для реально выполненной проверки с доказательством. SKIP, BLOCKED, FLAKY, таймаут и SETUP_FAILURE не означают успешной проверки.
8. Не публикуйте секреты и персональные данные. Не обращайтесь к production, не выполняйте push/merge/deploy/внешнюю отправку данных без явного разрешения в целевом проекте.
9. В отчёте укажите изменённые файлы, фактические проверки/результаты, непроверенное и остаточные риски.
