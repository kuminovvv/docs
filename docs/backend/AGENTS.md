# AGENTS.md — Backend

> **Область:** шаблон инструкций для backend-кода. В этом репозитории он расположен в `docs/backend/` как источник правил. В рабочем приложении разместите адаптированную копию в каталоге backend-кода. Корневого общего `AGENTS.md` здесь нет.

## Project overview — назначение и область

- Перед работой определите назначение сервиса, затронутые API-контракты, схемы данных, интеграции и критерии приёмки.
- Соблюдайте пользовательские требования и зафиксированные ограничения проекта. Конфликты кода, спецификаций, тестов и running behavior выявляйте, а не разрешайте молча.
- Для нетривиальной задачи зафиксируйте scope, план и риски; изучайте связанные файлы и зависимости, не сканируя репозиторий без причины.

## Tech stack — стек и версии

- Выясните реальные версии Go, HTTP-фреймворка, драйверов, БД и зависимостей по `go.mod`, конфигурации, миграциям и CI целевого проекта.
- **Go, PostgreSQL, JWT, очереди и outbox не являются обязательными технологиями по умолчанию.** Применяйте только относящиеся к проекту инструкции.
- Проверяйте версиозависимые API, флаги и рекомендации по официальной документации и release notes установленной версии; не обновляйте зависимости ради примера.

## Development — запуск и окружение

- Используйте реальные команды install/run/build/lint/test, Makefile, CI и конфигурацию целевого сервиса; не выдумывайте команды, адреса, порты и переменные окружения.
- Для проверки БД и внешних интеграций используйте изолированное тестовое окружение и синтетические данные. Production — только по отдельному разрешению.
- Перед изменением контрактов исследуйте потребителей API, миграции, зависимости и совместимость версий.

## Code conventions — архитектура и стиль

- Держите изменение минимальным, соблюдайте существующие пакеты, интерфейсы и инварианты; не вводите ненужные интерфейсы и абстракции.
- При использовании Go учитывайте `context`, корректную обработку ошибок, конкуррентность, отмену, закрытие ресурсов и race conditions.
- Для API обеспечивайте согласованные статусы и ошибки, валидацию входа, совместимость и проверку полномочий. Для БД — транзакции, миграции, идемпотентность и ограничения целостности.
- Подробные правила по реальному стеку: [Go](go.md), [HTTP API](api-contracts.md), [data integrity](data-integrity.md), [backend testing](testing.md), [observability](observability.md).

## Testing — проверка и доказательства

- Выполните доступные unit/integration/build, а для Go при необходимости `-race`, fuzz/property tests. Для изменений API/БД проверяйте негативные и конкурентные сценарии.
- При миграциях проверьте свежую и обновлённую схему, обратную совместимость и rollback strategy по риску.
- Фиксируйте команды, окружение, точный SHA, данные тестового сценария и безопасные артефакты. **PASS** означает фактически исполненную и подтверждённую проверку. `SKIP`, `BLOCKED`, `FLAKY`, timeout и `SETUP_FAILURE` — не PASS.
- Не меняйте verifier, тестовые ожидания или CI-gates ради маскировки регрессии; изменение самого verifier требует отдельного ревью baseline.

## Security — безопасность и приватность

- Не раскрывайте секреты, токены, персональные данные или приватные логи. Используйте синтетические данные для тестов и отчётов.
- Проверяйте authN/authZ на каждом критическом endpoint, ownership, IDOR, validation, rate limits и CSRF/replay, если применимо. Не считайте защитой UI-ограничение клиента.
- Для внешнего egress, SDK и telemetry определяйте получателя, состав данных и разрешения; не передавайте данные в другие сервисы без согласования.

## Delivery — коммиты, PR и завершение

- Проверьте Git status/diff, не затрагивайте чужие незакоммиченные изменения. Избегайте широкого рефакторинга вне scope.
- Push, merge, release, deployment и запуск CI с побочными эффектами — только с разрешения. Не объявляйте готовность при проваленных или пропущенных обязательных проверках.
- В отчёте перечислите изменения, реально выполненные проверки, точные результаты, непроверенное и остаточные риски.
- Для рискового diff используйте справочники [review/gates](../13-review-and-gates.md), [verification](../09-testing-and-verification.md), [security](../14-security-and-privacy.md) и [git/delivery](../10-git-and-delivery.md).
